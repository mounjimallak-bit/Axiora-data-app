# Axiora Data: Socio-Economic Analytics Platform for Morocco

An interactive **Streamlit** application for exploring, visualising and reporting on
Moroccan socio-economic indicators published by the **HCP** (Haut-Commissariat au
Plan, Morocco's national statistics institute).

The platform turns official statistical tables into interactive dashboards,
choropleth maps and automatically generated PDF reports.

**Live application:** https://axiora-data.streamlit.app/

## Overview

Public statistical data in Morocco is published mainly as PDF yearbooks and spreadsheets, which
makes comparison across regions and over time slow and error-prone. For Axiora Data
I transcribed a set of these tables (Souss-Massa region) by hand into Python
dictionaries, and the app exposes them through a single interface where an
indicator can be explored on a map and compared between provinces and years. There is no automated import from HCP files, so the data is only as good
as the transcription; `validate_data.py` exists to check it (see Data checks below).

The application covers **six thematic domains**, plus two cross-cutting modules:

### Thematic modules

| Module | Content |
|---|---|
| **Population** | Demographic structure, urban/rural distribution, growth by province |
| **Labour market** | Activity, employment and unemployment indicators |
| **Housing** | Housing development operations by province (completed, launched, in progress, planned) |
| **Finance** | Bank deposits and credit, investment projects, companies created, regional GDP by sector |
| **Education** | First-year enrolment, teaching staff by sex, public primary pupils by grade |
| **Poverty** | Poverty and vulnerability rates by territory |

### Cross-cutting modules

- **Report generator:** builds a structured PDF report from an uploaded dataset,
  including descriptive statistics, ranking tables and generated charts.
- **Axiora assistant:** a conversational module built on the Google Gemini API
  that answers natural-language questions about the tables in `hcpdata.py`. Its answers
  are generated by the model and are not checked automatically.

## Features

### Interactive visualisation

- Choropleth maps at provincial (**ADM2**) and commune (**ADM3**) level, rendered
  with GeoPandas and Plotly, and a dot map of enrolment and teaching staff by sex
  (1 dot = 40 people, placed at random inside the province)
- Comparative charts across territories and time periods
- Filtering by year, province and indicator

### Aggregate rows

HCP tables mix territories with the rows that add them up ("Souss-Massa", "Région",
"Total"). Those rows stay in the tables shown next to each chart, but each table is
split at its source with `sans_agregats()`, which removes the labels listed in
`LIGNES_AGREGAT` (an exact list, no pattern matching) and fails if the expected
aggregate row is missing. A total is therefore never plotted as if it were one more
province, and nothing is removed silently.

### Automatic PDF reporting

The report generator accepts a user-supplied dataset and produces a formatted PDF
containing:

- a generated table of contents
- descriptive statistics for the selected value column
- top / bottom ranking tables
- group summary tables
- charts exported as images and embedded in the document

Built with `fpdf` and a custom `PDF` class handling headers, footers and TOC entries.

### Conversational assistant

A question-answering module built on `gemini-2.5-flash` through the `google-generativeai`
SDK. Google has deprecated this SDK in favour of `google-genai`; a migration was tried, failed
in production and was rolled back, so it will be redone once it can be tested against the real
API. Every call sends the tables of
`hcpdata.py` and their sources as system instructions, with a low temperature (0.2), plus the
last six exchanges so that follow-up questions keep their context. Use is limited to 6 questions
per minute per session and 20 per minute for the whole server, and to 500 characters per question.
The answers are generated by the model and are not verified automatically against the tables.
When a call fails, the app shows the error code and writes it to the server log, without the key.
The API key is read from Streamlit secrets and is never stored in the repository.

### About the shapefiles

The two `mar_admbnda_*` directories contain the official administrative boundary
shapefiles for Morocco. They are **required**: `app.py` loads them through
GeoPandas to render every choropleth map. Removing them disables all
cartographic features.

## Running Locally

### 1. Clone and install

```bash
git clone https://github.com/mounjimallak-bit/Axiora-data-app.git
cd Axiora-data-app
pip install -r requirements.txt
```

### 2. Configure the API key

The conversational assistant requires a Google Gemini API key. Create
`.streamlit/secrets.toml`:

```toml
GEMINI_API_KEY = "your_api_key_here"
```

This file is git-ignored. All other modules work without it.

Last clean install tested (Python 3.13, `pip install -r requirements.txt`, November 2026):
streamlit 1.66.1, pandas 3.1.1, numpy 2.5.4, plotly 5.24.1, geopandas 1.2.0,
google-generativeai 0.8.6, fpdf 1.7.2, matplotlib 3.11.2, openpyxl 3.1.5, Pillow 13.0.0.
`requirements.txt` pins only Streamlit and Plotly; to reproduce this environment exactly,
install these versions.

### 3. Run

```bash
streamlit run app.py
```

The application opens at `http://localhost:8501`.

## Data checks

```bash
python validate_data.py
```

The script parses the tables in `hcpdata.py` and `app.py` without running the app
and checks that every column of a table has the same length, that totals match
their parts (Urbain + Rural, Hommes + Femmes, regional row vs provinces), that every
province name reaches a polygon, and it reports zeros in rate columns for review (a zero
rate often stands for a missing value).
For the commune poverty map it reproduces the app's join exactly (province and
commune together, Souss-Massa only) and requires every data row to reach exactly one
polygon of its own province: a commune name alone is not unique in Morocco (Tabia
and Oulad Aissa also exist in other regions). It exits with code 1 while errors remain.

Sums of counts must be exact (a rounding margin of 0.05 applies only to values with
decimals), and the communes of each province must add up to its total. Every table that
`app.py` repeats from `hcpdata.py` is compared value by value with its copy; the copy is
found from the structure of the table and its year, never from values that already agree,
and the housing tables, which all share one structure, are paired by name (`COPY_OF`).

The 93 tables it reads are 48 tables in `hcpdata.py` and 45 in `app.py`, all 45 of which
are copies of a table in `hcpdata.py`. On the current data it reports no errors and two
known discrepancies, listed in `KNOWN_DISCREPANCIES` and reported as warnings until they
are checked against the publication: in the 2018 first-year enrolment table, boys plus girls
in Tiznit make 3,828 while the total is 3,826 (every column adds up, which points to the
published table), and in the 2017 investment projects table the Total row differs by 1 from
the sum of the provinces in three columns.

These checks test internal consistency only: a value can be consistent with its totals and
still be mistyped. They do not compare the tables with the HCP publications.

```bash
python test_validate_data.py
```

Introduces one error at a time in a temporary copy of the data (a count total off by 1 in
both copies, the regional population off by 0.75 %, a commune total off by 1, an `app.py`
copy that differs, a 2018 table filled with the 2017 figures, a housing table filled with
another housing table) and checks that `validate_data.py` reports each of them, and that the
unmodified data pass.

## Poverty analysis (case study)

```bash
python analyse_pauvrete.py --figures
```

Reproduces every number of the poverty analysis in the portfolio case study from
`hcpdata.py`: distributions of the rates of the 179 geographic units (175 communes and
4 urban centres) with a rate in all three years, changes by unit, results by territory
both with each unit counted once and with the population-weighted rate the HCP publishes
for each province ("Ensemble" row), and writes the two box plots to `figures/`. No
hypothesis test is computed: the units are the whole set with published rates, not a
sample, so the results are descriptive.

## Data provenance

The tables are transcribed from the public statistical publications of the HCP
Souss-Massa regional directorate (hcp.ma/region-agadir): the *Annuaire
statistique régional* for 2016, 2017 and 2018 (the 2017 yearbook also gives the
RGPH 2004 and 2014 legal population), the regional results of the national
employment survey (ENE) for 2017 to 2020, and the commune poverty sheets *Evolution
des indicateurs de pauvreté 2004, 2007 et 2014*. Each table's source is recorded in
`SOURCES` in `hcpdata.py`, and each page of the app states its own. Every
value of the tables taken from the 2016, 2017 and 2018 regional yearbooks was
compared with the yearbook text; this found and corrected two transcription
errors (four cells of the 2017 administrative division, and the 2015 column of
the companies-created table, whose three values had been swapped).
In the three labour-market tables for 2017–2020 (ENE
survey), the 2019 and 2020 values match the HCP's published ENE indicators and the
2019–2020 yearbooks; the 2017 and 2018 values, and the rates for people with a
diploma (published by the HCP split into two levels), could not be matched to a
published table.
The internal totals (province rows against the regional
row, Urbain + Rural, subtotals against their parts) are enforced by
`validate_data.py`.

Three points are documented rather than checked automatically:

- One published figure does not add up and is replaced: in the 2016 yearbook, the
  unemployed aged 35–44 in the region are printed as 12,984, while the urban and rural
  parts (9,538 + 2,510) and the row total both give 12,048, the value used. The app says
  so under the table.

- The RGPH 2004 urban population of Chtouka-Aït Baha is not given directly in any
  HCP sheet. It is set to 39,694, the value for which the province figures add up
  exactly to the published regional total; this is an inference, not a published
  figure. The app says so under every table, map and comment that shows it.
- On the commune poverty map, the central KPI is the unweighted mean of commune
  rates (not a population-weighted regional rate) and is labelled as such.

The PDF report generator operates on a file the user uploads, so its output
depends on that file. It reads numbers written in French or English format ("1 234,5", "1.234,5",
"1,234.5", "12,7 %", "(12)" for -12; a single comma is read as a decimal comma)
and drops aggregate rows before ranking or summing: labels that are a total ("Total",
"Ensemble", "Sous-total…"), labels ending with a subtotal ("Province de Tata Ensemble",
"… Urbain", "… Rural"), and a lone "Région …" row in a file of other territories. The
PDF states how many rows were dropped, and `validate_data.py` does not inspect uploaded files.
Charts are written to a temporary directory that is deleted as soon as the PDF is built.
A PDF is offered for download only while the file and the settings it was built from are
unchanged. Characters outside the Latin alphabet cannot be written with the PDF's built-in
fonts; the app says so before building the report instead of replacing them silently. Uploads
are limited to 10 MB (`.streamlit/config.toml`).

## Notes and Limitations

- The interface language is **French**, matching the source data.
- The 2004, 2007 and 2014 poverty rates come from three separate HCP poverty
  maps; their comparability over time has not been checked against the HCP
  methodology notes.
- Indicator coverage depends on what HCP publishes; some series are available for
  a limited number of years.
